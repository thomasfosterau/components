## 0.5.0

### Minor Changes

- a8e4098: New `BottomSheet` in `feedback`: a panel that rises from the bottom edge and rests at one of several `detents` (fractions of the viewport height, or `'content'`), with a bindable `detent`. Its grabber is a focusable `role="slider"` (`handleLabel`, `detentLabels` as `aria-valuetext`) moved by ↑/↓, Home and End, or dragged with the pointer: it snaps to the nearest detent, or one further on a flick, and dragging below the lowest closes it while `dismissible`. Modal by default, on the same dialog frame as `Drawer`; `modal={false}` renders a named region that leaves the page usable, where Escape collapses rather than closes. New type `SheetDetent`.
- 89ba5de: `DataGrid`: copy and paste a cell. In an editing grid's navigation mode, Ctrl/⌘+C copies the focused cell's text (its `format`, a date's ISO form, else the value), and Ctrl/⌘+V pastes into an editable cell: the text is read as its editor would read it (`parse` for text, a number, a select option by value or label, an ISO date), checked by `validate` and committed as one undoable edit without moving. Text the cell cannot take commits nothing and marks the cell in error with the new `pasteFailedLabel` (default "That can't go in this cell.") or the validation messages.
- 72bf89d: `DataGrid` (editing): Shift+arrow keys select a block of cells (`aria-selected`, with `aria-multiselectable` on the grid), which Ctrl/⌘+C copies as tab-separated lines. A block pasted from a spreadsheet fills the cells from the block's top-left or the active cell, and one value pasted over a selected block fills every cell in it: all or nothing, as one undoable edit. A block that runs past the grid announces the new `pasteOutsideLabel` prop.
- 2690757: `DataGrid`: undo and redo for cell edits (#424). An editing grid keeps an undo history (`undo`, on by default): in navigation mode Ctrl/⌘+Z undoes the last committed edit and Ctrl/⌘+Shift+Z or Ctrl+Y redoes it. In `'batch'` an undo restores `changes` to its previous state; in `'cell'` it calls `onCellCommit` with the inverse change, with the same busy state and rollback. Each undo and redo is announced through the grid's polite region (`undoneLabel`, `redoneLabel`). New type `CellTarget<T>` (`{ row, column }`), which `CellError<T>` now extends.
- 532a1e8: Add `DialogHost` and `getDialogs()`: `await dialogs.confirm(…)`, `.prompt(…)` and `.alert(…)` open the library's dialogs from code, one at a time, and resolve with the answer. An `AbortSignal` closes a request as cancelled. `Dialog`, `ConfirmDialog` and `PromptDialog` gain `finalFocus`, the element to focus on close.
- 330879b: `ListDetailLayout`: a `resizable` divider. From `expandAt` up the border between the panes becomes `Splitter`'s window-splitter handle (a focusable `separator` named by `handleLabel`, default "Resize list", that controls the list region), moved by the arrow keys, Home / End or a drag. `listSize` (the list's width in percent of the layout) is bindable and clamped to `minListSize` / `maxListSize` (15 / 60); until it is set the list keeps its `listWidth` token. `onListResize` reports each settled size. `Splitter` now draws the same shared handle.
- c58b512: New `ListGroup` and `ListRow` (`data`): an inset, rounded group of rows under a heading for settings screens, and one general-purpose row with leading content, overline / headline / supporting text and trailing content. A row with `href` is one link and with `onclick` one button, named by its headline and trailing value; any other row is a control row whose `trailing` snippet gets `labelledBy` / `describedBy` so its switch or select is named after the row. `LinkListItem` is now built on `ListRow`, with its props unchanged.
- e3ab0d1: `Table` / `DataGrid`: select-all's second step. Once every row on the page is selected and there are more rows than the page, the selection toolbar offers "Select all <n>" (`selectAllTotalLabel`); taking it makes the count read "All <n> selected" (`allSelectedLabel`) beside a "Clear selection" button (`clearSelectionLabel`), which takes focus. `DataGrid` wires it up itself and selects every filtered row on every page; `Table` takes `selectAllTotal` and `onSelectAllTotal` for a paged caller.
- 26046a3: New `Splitter` in `layout`: two panes, side by side or stacked, with an APG window-splitter handle between them (a focusable `role="separator"` named by `handleLabel`, with its value range and `aria-controls`). Drag it, or use the arrow keys (mirrored under RTL), Home and End; with `collapsible`, Enter collapses the leading pane and restores it. `size` (percent of the leading pane) is bindable and clamped to `minSize`/`maxSize`, and `onCommit` reports each settled size once per key press or drag. Nest one in a pane for three-way layouts. No new dependency.
- 9c1a899: `Toaster`: a toast can carry one action ("Bed deleted · Undo"). `getToaster().add({ title, action: { label: 'Undo', onAction } })` renders a button that runs `onAction(signal)` and dismisses the toast once it settles; while it is pending the button is busy, and a rejection keeps the toast, sticky and in the error tone, with `formatActionError(error)` in place of its description. A toast with an action lives `actionDurationMs` (default 10 s) and its text includes a visually hidden `actionHint` ("Undo available"). Every toast's timer now pauses while the pointer is over it, focus is inside it or the page is hidden. New `ToasterApi.result(id)` resolves with how a toast ended (`'action'`, `'dismissed'` or `'timeout'`), and new types `ToastAction` and `ToastOutcome`.

## 0.4.0

### Minor Changes

- 4f209db: **Breaking (`/entity-form`):** `EntityForm` now renders `@thomasfosterau/effect-forms-svelte` 0.4 definitions, and the optional peer moves from `^0.3.1` to `^0.4.0`. effect-forms-svelte 0.4 addresses fields by typed focus instead of string path, so no 0.3 release fits. A consumer of `/entity-form` must:

  - upgrade `@thomasfosterau/effect-forms-svelte` to `^0.4.0`;
  - install that release's new required peer, `@thomasfosterau/effect-ext` `^0.1.0 || ^0.2.0` (its 0.3 line is outside the form library's range);
  - run Node 22.18 or later, which effect-forms-svelte 0.4 requires.

  Consumers that never import `/entity-form` are unaffected. The `svelte` (`^5.40.0`) and `effect` (`^4.0.0`) peer ranges are unchanged.

  `EntityForm`'s props are unchanged, but two of their types follow the form library:

  - `enhance` receives a 0.4 `FormStore` over the definition's all-string input record (`Readonly<Record<string, string | undefined>>`), validated by the mode's `createInput` / `updateInput`. It must return that store's `FormProps`. A custom `enhance` that reads the store uses the 0.4 names: `isPosted` / `isValid` for `posted` / `valid`, `formErrors` for the root messages, and a focus (`form.root.key('title')`) for `errorsAt` / `get` / `set`. `/kit`'s `enhanceForm` can be passed directly.
  - `fieldProps[key]` is typed as the form library's `WidgetOwnProps`: a widget's own props, partial, without the renderer-owned bridge keys. As before, `name`, `value`, `onChange` and `errors` given there are overridden by the bridge.

  What `EntityForm` renders is unchanged: the controls, their names and ids, the error summary and the save bar.
